# Spring AI Flow 网站操作手册

> 面向业务用户：手把手讲解网站七大页面的操作流程。
> 建议先阅读第 1 节「快速上手」，用预置示例流程完整跑一遍，再学习流程编排。

## 1. 快速上手（5 分钟跑通第一个流程）

系统预置了 3 个示例流程，无需任何配置即可体验：

1. 浏览器打开系统地址（默认 `http://localhost:8080/`），进入**工作台**
2. 在「示例模板」区域找到 **营业执照智能识别** 卡片，点击 **▶ 立即运行**
3. 在运行页左侧上传一张营业执照图片（或粘贴图片 URL），点击 **▶ 提交运行**
4. 右侧「执行视图」实时展示节点状态（排队 → 执行中 → 成功），完成后点击节点查看结构化识别结果
5. 结果满意后，可在左侧「运行历史」或顶部导航 **运行历史** 中随时回看

体验并行编排：在工作台运行 **订单风险并行审核**，同时上传发货单据图片 + 订单 Excel，观察两个节点并行执行、结果汇流到「综合风险裁定」。

## 2. 页面总览

顶部/左侧导航固定入口：

| 导航项 | 页面 | 用途 |
|---|---|---|
| 工作台 | `/dashboard` | 数据统计总览 + 场景入口 + 示例模板 |
| 流程库 | `/flows` | 流程卡片管理（关键词检索 + 分页）：运行 / 编辑 / 复制 / 删除 |
| + 新建流程 | `/flow-editor` | 打开空白编辑器 |
| 知识库 | `/knowledge` | 上传文档建知识库，供「知识检索」节点做 RAG 增强问答 |
| 场景体验 | `/playground` | 单节点即席体验（无需建流程） |
| 运行历史 | `/runs` | 全部运行记录（四条件检索 + 分页）与详情回看 |

侧栏底部有当前 AI 模式胶囊（如 `llm · aliyun/qwen3.8-flash`），提示当前 provider 与默认模型；旁边还有两个工具按钮：

- **◐ 主题**：弹出主题选择菜单，内置三套主题 —— **晨雾白**（默认浅色）/ **星夜蓝**（深色）/ **暖沙杏**（暖色调），选择即生效并记住偏好（下次打开自动应用）
- **‹ / ›**：收起 / 展开左侧菜单栏；收起后仅保留图标，鼠标悬停图标可见提示，再次点击展开

> 主题与侧栏状态均保存在浏览器本地，刷新页面不会丢失。

## 3. 工作台（Dashboard）

进入系统默认页，包含三个区域：

1. **统计概览**：运行总数、成功率、平均耗时、累计 Tokens、模型调用次数，五张统计卡片来自运行历史实时统计
2. **五大场景入口**：文本理解 / 图片识别 / JSON 处理 / Excel 处理 / 组合处理，点击任意场景卡直达「场景体验」并自动选中对应场景
3. **示例模板**：3 个预置流程卡片，展示描述与节点类型标签，支持 **▶ 立即运行** 与 **编辑**

## 4. 场景体验（Playground）

不建流程、直接体验单个节点能力的「即席」页面，适合快速调试提示词。

### 操作步骤

1. **选场景**：点击顶部场景 Tab —— 📝 文本 / 🖼️ 图片 / 🧩 JSON / 📊 Excel / 🧬 组合，表单按场景动态显示所需输入项
2. **填指令**：「处理指令」必填，告诉模型做什么
3. **给输入**（按场景）：
   - 文本：粘贴待处理文本
   - 图片：填图片 URL 或本地上传图片
   - JSON：粘贴 JSON 文本
   - Excel：上传 .xlsx/.xls 文件
   - 组合：文本 + 图片 + Excel 可任意组合
4. **定输出**：
   - 输出类型选 `json` 时，在「字段契约」中每行定义一个字段：`字段名|说明|必填`（必填填 1），例如 `ship_no|运单号|1`
   - 选 `text` 则输出纯文本
5. **可选高级项**：系统提示词（角色设定）、模型覆盖、温度
6. **运行**：点击 **▶ 运行场景**；勾选「打字机流式」则以 SSE 流式逐字输出，否则等待完整结果并展示结构化面板（输出原文 / 解析 JSON / 模型 / 耗时 / Token）

> Playground 与正式流程使用同一套节点执行引擎，调试好的提示词和字段契约可直接搬到流程编辑器。

## 5. 流程库（Flows）

全部流程的卡片视图，每个卡片展示名称、描述与节点类型标签。

- **搜索与分页**：顶部搜索框输入关键词（模糊匹配流程名称与描述），输入即自动过滤（防抖）；卡片较多时底部分页条翻页，每页 12 个
- **＋ 新建空白流程**：左上角按钮，进入空白编辑器
- 每个流程卡片的操作：
  - **▶ 运行**：进入该流程的运行页
  - **编辑**：进入编排画布
  - **复制**：基于该流程复制一份新流程（名称自动追加"（副本）"）
  - **删除**：删除流程（弹出确认弹窗，需点击「删除」确认，不可恢复）

## 6. 流程编辑器（Flow Editor）

可视化 DAG 编排画布，三栏布局：左侧节点面板 / 中间画布 / 右侧属性面板，顶部工具栏。

### 6.1 基本操作

- **填写流程信息**：顶部输入流程名称（必填，保存前需填写）与描述（可选）
- **添加节点**：从左侧面板**拖拽**节点类型到画布任意位置，13 种类型：
  - 📝 文本理解（纯文字输入）/ 🖼️ 图片识别（图片多模态输入）/ 🧩 JSON 处理 / 📊 Excel 处理 / 🧬 组合处理（多源组合输入）
  - 🔀 条件路由（按模型选择的分支走不同连线）/ 🔧 工具调用（时间 / 计算 / 网页抓取 / JSONPath）
  - 📚 知识检索（知识库 RAG 增强问答）/ 🎨 图片生成（提示词文生图）
  - 🛡️ 内容审核（违规类别检测分流）/ ⚖️ 输出评估（LLM-as-judge 质量打分）
  - 📦 子流程（引用其他流程作为宏）/ 🧲 聚合（不经模型合并多上游输出，零 Token）
- **连线**：从源节点**右侧圆点**拖出，连到目标节点，即建立执行顺序（上游成功后下游才会执行）；条件路由节点的出线可设置**分支条件**（见 6.4）
- **删除节点**：节点卡片右上角 **✕**（弹出确认弹窗，确认后删除，相关连线自动移除）
- **删除连线**：点击任意连线，弹出确认弹窗，确认后删除（之后可重新拖拽连接）
- **编辑节点属性**：点击节点卡片，右侧属性面板展开编辑（见 6.3）

### 6.2 画布平移与缩放

画布区域支持自由平移与缩放，节点再多也不会被遮挡：

| 操作 | 方式 |
|---|---|
| 平移画布 | 在画布**空白处按住左键拖动**，或**按住鼠标中键**在任意位置拖动 |
| 缩放画布 | 在画布上**滚动鼠标滚轮**（以鼠标位置为中心缩放），或使用右下角控件 **− / 100% / ＋** |
| 适应全貌 | **双击**画布空白处，自动缩放并居中显示全部节点 |
| 画布全屏 | 点击右下角 **⛶** 进入全屏（按钮变为 **⤢**），再次点击或按 **Esc** 退出全屏；进入 / 退出后自动适应全貌 |
| 重置缩放 | 点击右下角百分比数字，恢复 100% |

缩放范围 25% ~ 250%，当前缩放比例实时显示在右下角控件中。

### 6.3 节点属性面板

选中节点后可配置（通用属性 + 当前节点类型专属属性）：

| 属性 | 说明 |
|---|---|
| 节点名称 | 画布与运行页展示名 |
| 处理指令 | 必填；支持 `{{变量}}` 引用输入与上游产出（如 `{{doc.json.ship_no}}`） |
| 系统提示词 | 可选角色设定 |
| 输出类型 | `json` / `text` |
| 字段契约 | json 类型时逐条定义：字段名 / 说明 / 是否必填 |
| 模型覆盖 / 温度 | 可选，覆盖全局默认 |
| 图片 URL | 图片类节点可直接绑定素材 |
| 候选分支 | 条件路由专属：添加若干「分支名 + 说明」，模型从候选中输出 `{"route":"分支名"}` 决定走向 |
| 内置工具自动挂载 | 工具调用专属：自动挂载全部内置工具（当前时间 / 数学计算 / 网页抓取 / JSONPath 提取），模型按需自主调用 |
| 知识库 / TopK | 知识检索专属：下拉选择知识库，TopK 控制召回条数 |
| 会话记忆轮数 | 可选：填入后该节点携带同一会话最近 N 轮对话历史（需运行时传入会话ID） |
| 子流程 | 子流程专属：下拉选择要引用的其他流程 |
| 聚合策略 | 聚合专属：拼接（concat）/ JSON 字段合并（jsonMerge）/ 模板渲染（template） |

> 内容审核 / 输出评估 / 聚合三类节点允许不填处理指令（引擎按各自默认逻辑执行）。

### 6.4 连线属性（条件路由分支）

点击**条件路由节点的出线**，弹出轻量连线面板：

- **分支条件**：下拉选择该路由节点配置的候选分支之一（默认分支为兜底项）；运行时模型输出 `{"route":"分支名"}`，与分支名一致的连线被激活，其余分支未命中时走「默认分支」
- 删除连线同样在该面板操作

### 6.5 保存与校验

- **校验**：实时检查（节点完整性、连线合法性、循环依赖等），错误以列表展示，可保存前自检
- **保存**：保存到 MySQL `flow_definition` 表，工具栏显示保存状态
- **▶ 运行**：保存后直接跳转运行页提交运行

## 7. 运行页（Run）

左侧输入面板 + 右侧实时执行视图。

### 7.1 提交运行

左侧表单按流程包含的节点类型**动态显示**所需输入：

- **输入文本**：TEXT / JSON / COMBINED 等场景
- **图片 URL / 上传图片（可多选）**：IMAGE / COMBINED 场景
- **Excel 文件**：EXCEL / COMBINED 场景（支持 .xlsx / .xls，自动解析表头与数据行）
- **音频文件（可选）**：上传后自动转录，转录文本与输入文本合并
- **会话ID（可选）**：多轮记忆；流程中配置了「会话记忆轮数」的节点会携带同一会话最近 N 轮对话历史

点击 **▶ 提交运行**，立即返回 runId 并开始执行。

### 7.2 实时执行视图

- **DAG 分层展示**：节点按拓扑层级排布，实时状态标识（等待 / 执行中 / 成功 / 失败 / 取消），并行分支一目了然
- **进度条**：展示整体完成进度
- **节点详情**：点击任意节点查看输出原文、解析 JSON、模型、耗时、Token
- **失败处理**：失败节点展示错误信息；其下游节点标记「上游节点失败，本节点已取消」

### 7.3 回看

运行结束后可直接在本页回看，也可从「运行历史」进入任意历史运行。

## 8. 运行历史（Runs）

顶部统计卡片（运行总数 / 成功率 / 平均耗时 / 累计 Tokens / 模型调用次数）+ 运行记录表格，按开始时间倒序：

**筛选与分页**：表格上方筛选栏支持四个条件组合检索 —— 运行ID（模糊）、流程（名称或ID模糊）、状态（精确：成功 / 失败 / 运行中）、时间范围（开始时间起止日期）；点击「查询」应用，「重置」清空；底部分页条翻页。

| 列 | 说明 |
|---|---|
| 运行ID | `r_` 前缀，点击「详情」进入运行页回看 |
| 流程 | 流程名称 |
| 状态 | ✓ 成功 / ✗ 失败 / ⏳ 运行中 |
| 节点进度 | 成功节点数 / 总节点数 |
| 耗时 / Tokens | 单次运行总耗时与 Token 消耗 |
| 时间 | 开始时间 |

> 注意：运行历史持久化保存在 MySQL 中（`flow_run` / `flow_node_execution` 表），**服务重启后完整保留**；流程定义同样入库存储。

## 9. 知识库（Knowledge）

上传业务文档，切分向量化后供流程中的「知识检索」节点引用，实现 RAG 增强问答。

### 9.1 新建知识库

1. 点击右上角 **＋ 新建知识库**，填写名称与描述，确认后卡片出现在列表中

### 9.2 上传与管理文档

1. 点击知识库卡片打开详情弹层
2. 点击 **⬆ 上传文档** 选择文件（支持 .txt / .md / .json / .csv / .log / .yml / .xml / .html 等纯文本格式）
3. 文档自动切片并向量化入库，列表展示文档名、切片数、状态与上传时间
4. 不需要的文档点击行尾 **🗑 删除**（连同其向量切片一并删除）；删除整个知识库同理

### 9.3 检索调试

详情弹层底部输入查询内容、选择 TopK（召回条数），点击 **检索** 验证效果：命中片段按相似度得分排序展示，可据此调整文档内容或 TopK。

### 9.4 在流程中使用

编辑器拖入 **📚 知识检索** 节点，在属性面板选择目标知识库并设置 TopK；节点执行时自动检索知识库，将相关片段注入提示词辅助作答。

## 10. 典型场景操作示例

### 10.1 从零编排「客户线索清洗」流程

1. 流程库 → **＋ 新建空白流程**，填写名称「客户线索智能清洗」
2. 拖入 3 个节点：📝 文本理解（命名为「需求提取」）、🧩 JSON 处理（「结构化入库」）、📝 文本理解（「跟进话术」）
3. 依次连线：需求提取 → 结构化入库 → 跟进话术
4. 配置「需求提取」：指令「从线索文本中提取客户需求」；输出类型 json，字段契约如 `demand|核心需求|1`
5. 配置「结构化入库」：指令中引用上游 JSON，如 `按以下 JSON 整理客户信息：{{demand.json}}`；定义入库字段契约
6. 配置「跟进话术」：指令「针对客户 {{demand.json.demand}} 生成跟进话术」；输出类型 text
7. 点 **校验** 确认无误 → **保存** → **▶ 运行**，粘贴一段原始线索文本提交

### 10.2 编排「并行 + 汇流」流程

1. 新建流程，拖入 4 个节点：🖼️ 图片识别（A）、📊 Excel 处理（B）、🧬 组合处理（C）
2. 连线 A → C、B → C（A 与 B 无连线，将自动并行执行）
3. C 的指令分别引用 `{{A.json}}` 与 `{{B.json}}` 做综合裁定
4. 运行时同时上传图片与 Excel，在执行视图观察两支并行、汇流执行
