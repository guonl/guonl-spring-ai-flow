### 步骤 6：P0 联调验收（mock 模式）

- `--flow.ai.provider=mock` 启动（前台进程，**不用 nohup**，端口避开 8080）。
- 验收清单：
  1. 悬浮窗新建会话 → 发「你好」→ 流式返回能力清单（兜底意图）。
  2. 发「有哪些流程」→ mock 走真实 `list_flows`，返回流程表格。
  3. 刷新页面 → 会话列表保留 → 独立页续聊同一 conversationId。
  4. 删除会话 → 列表与记忆同步清除。
  5. 切 `provider=llm` 复测一轮真实流式对话 + 二轮记忆追问。
- 全绿后 P0 完成，更新本文件勾选。

## 阶段二（P1 · 工具赋能）

### 步骤 7：AssistantTools 只读工具集

| 工具 | 依赖 | 说明 |
| --- | --- | --- |
| `assistant_list_flows(keyword)` | FlowStore.search | 流程列表（id/名称/节点数/更新时间） |
| `assistant_get_flow(flowId)` | FlowStore.require | 流程定义结构摘要（节点/连线/prompt 截断） |
| `assistant_get_run(runId)` | RunStore | 运行快照 + 节点执行记录（状态/错误/耗时/token） |
| `assistant_recent_failed_runs(limit)` | RunStore | 近期失败运行列表 |
| `assistant_search_knowledge(query, topK)` | KnowledgeService 向量检索 | 命中片段（来源文档+得分） |

- 装配：独立 `ToolCallbackProvider`，`toolSet=assistant` 时挂载（`tools-enabled=true` 才注册）。
- 验证：mock 下「有哪些流程」「诊断 runId xxx」意图真实走工具，tool_trace 事件有轨迹。

### 步骤 8：save_flow 写工具（NL 建流程）

- `assistant_save_flow(name, description, nodesJson, edgesJson)`：入参为符合 `FlowDefinition` 结构的 JSON（13 种 NodeType、边 from/to/condition）；内部复用 `FlowEngine.validate` 校验，失败把 errors 回灌模型自纠一次（最多 1 轮）；成功保存并返回 `{flowId, editorUrl:/flow-editor?flowId=xx}`。
- 仅 `provider=llm` 且 `tools-enabled=true` 时注册（mock 下返回引导文案，见技术方案 §7）。
- 验证：llm 模式说「帮我建一个 Excel→JSON→文本总结的流程」→ 保存成功 → 画布打开无误。

### 步骤 9：P1 联调验收 + 文档收尾

- 验收：诊断对话（真实失败 run 归因合理）、建流程闭环、知识检索命中。
- 文档：`docs/usage.md` 增「AI 助手」章节；features/README 功能清单补条目；本文档勾选完成。

### 步骤 11：会话增强（重新生成 / 导出 / 反馈）

| 项 | 内容 |
| --- | --- |
| 重新生成 | `ChatRequest.regenerate`；`AssistantService.truncateLastTurn` 截断 JDBC 记忆最后一轮（从尾部最后一条 USER 起丢弃，`saveAll` 全量重写），前端 meta 加「⟳ 重新生成」按钮（仅最后一条有效，重发不新增用户气泡），会话计数不重复累加 |
| 导出 | 前端维护 `turns`（select/send/finish/stop 同步），头部「⇩」导出 Markdown（标题+元信息+分节轮次）Blob 下载 |
| 反馈 | `sqls/p2_assistant.sql`（`assistant_feedback` 表：会话+内容指纹唯一，upsert 改评/删除取消；`SPRING_AI_CHAT_MEMORY.content` 扩 MEDIUMTEXT）；后端 `AssistantFeedbackService` + `POST /api/assistant/feedback` + `GET /api/assistant/sessions/{conv}/feedback`；指纹为 djb2 32位hex（前后端同算法）；前端 meta 加 👍/👎（重复点击取消，历史消息按指纹高亮），删除会话连带清反馈 |
| 验证 | regenerate 前后记忆条数不变且最后一轮被替换；反馈 upsert/改评/取消三态 + 历史高亮 |

### 步骤 12：助手多模态（贴图问排版 / 报错截图）

| 项 | 内容 |
| --- | --- |

| 前端 | 输入栏 🖼️ 按钮（mock 隐藏）+ 输入框粘贴截图；预览条可删；发送前 canvas 压缩（长边≤1568px、JPEG q0.9，小 PNG 直传）；用户气泡内显示缩略图；上限 3 张 |
| 记忆 | 图片不写入 ChatMemory（advisor 只存文本），content 列扩 MEDIUMTEXT 兜底 |
| 验证 | llm 模式贴图提问，模型准确描述图片内容 |

## 风险与应对

| 风险 | 应对 |
| --- | --- |
| MCP annotation-scanner 误扫 AssistantTools | AssistantTools 不注册到 MCP provider；命名空间隔离（§4） |
| SSE 经反代被缓冲 | 心跳注释行 + 响应头 `X-Accel-Buffering: no` |
| ChatMemory 表膨胀 | 会话删除连带清理；P2 可加定期清理任务 |
| 工具幻觉参数（不存在的 flowId） | 工具内 require 失败返回可读错误，模型据此向用户澄清 |
