## 2. 数据模型

### 2.1 新表 `assistant_session`（DDL 交付至 `sqls/` 目录，用户手动执行）

```sql
CREATE TABLE IF NOT EXISTS `assistant_session` (
  `id`            BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `conversation_id` VARCHAR(64) NOT NULL                COMMENT '会话ID（与 SPRING_AI_CHAT_MEMORY.conversation_id 对齐）',
  `title`         VARCHAR(128) NOT NULL DEFAULT '新会话'   COMMENT '标题（首条消息前40字）',
  `message_count` INT          NOT NULL DEFAULT 0          COMMENT '消息条数（用户+助手）',
  `created_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_conversation` (`conversation_id`),
  KEY `idx_updated` (`updated_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci
  COMMENT='AI 助手会话元数据（消息正文存 SPRING_AI_CHAT_MEMORY）';
```

- 消息正文不建新表：`SPRING_AI_CHAT_MEMORY`（Spring AI JDBC ChatMemory，`initialize-schema=always` 已建）按 conversationId 存角色+文本，读取消息历史直接走 ChatMemory API。
- 实体 `AssistantSessionDO` 字段与表一一对应；Mapper 提供：insert / selectByConversation / list(limit 50, updated_at 倒序) / updateTitle / deleteByConversation / incrMessageCount。

### 2.2 会话 ID 规则

- conversationId：`a_` + 32 位随机 hex（前端生成或后端生成均可，后端兜底）；与流程运行 conversationId（`f_` 等）命名空间隔离。

## 3. API 契约（/api/assistant/**）

| 方法 | 路径 | 说明 | 请求体/参数 | 响应 |
| --- | --- | --- | --- | --- |
| POST | `/api/assistant/chat` | 发送消息，SSE 流式返回 | `{ "conversationId": "a_xx"(可空=新建), "message": "..." }` | `text/event-stream`（事件见 §5） |
| GET | `/api/assistant/sessions` | 会话列表 | - | `SessionView[]`（updated_at 倒序，最近 50） |
| GET | `/api/assistant/sessions/{conversationId}/messages` | 会话消息历史 | - | `[{ role, content, createdAt }]`（读 SPRING_AI_CHAT_MEMORY） |
| DELETE | `/api/assistant/sessions/{conversationId}` | 删除会话（元数据+记忆） | - | `{ "deleted": true }` |
| GET | `/api/assistant/status` | 助手状态（悬浮窗角标/独立页横幅用） | - | `{ "enabled": true, "provider": "mock|llm", "model": "...", "toolsEnabled": false }` |

- chat 为 SSE 响应：请求头 `Accept: text/event-stream`；结束后 emitter complete。异常以 `event: error` 下发（见 §5）。
- 沿用 `ApiExceptionHandler` 全局异常语义；message 为空 / 超长（>4000 字）返回 400。

## 4. AssistantService 编排逻辑

```java
// 伪代码
public void chat(ChatRequest req, Consumer<ChatEvent> sink) {
    String conv = ensureConversation(req);          // 无 conversationId 则新建 + 建会话元数据
    sink.accept(event("start", {conversationId: conv}));

    InvokeRequest invoke = InvokeRequest.builder()
        .bizKey("assistant")
        .systemPrompt(promptLoader.systemPrompt())   // 手册摘要（§6）
        .userPrompt(req.message())
        .conversationId(conv)                        // JDBC ChatMemory 自动带历史
        .memoryTurns(props.getMemoryTurns())         // 默认 10
        .temperature(props.getTemperature())         // 默认 0.3
        .toolSet(props.isToolsEnabled() ? "assistant" : null)
        .onDelta(text -> sink.accept(event("delta", {text})))
        .build();

    InvokeResult result = isMock()
        ? mockResponder.reply(invoke, sink)          // 意图路由（§7），工具真实调用
        : aiInvoker.invoke(invoke);                  // llm：SpringAiInvoker.stream 驱动 onDelta

    sink.accept(event("tool_trace", result.toolCalls()));   // 若有工具调用（折叠展示）
    sink.accept(event("done", {content, model, usage}));
    sessionService.incrMessageCount(conv, 2);        // 用户+助手两条
}
```

- llm 模式下 `SpringAiInvoker.stream()` 为真实流式实现：`ChatClient.prompt().stream().content()` 逐块回调 `onDelta`；工具调用（内部工具执行）对前端透明，仅在最终 `tool_trace` 汇报。
- 助手工具（AssistantTools）以 `@Tool` 注解注册，经独立 `ToolCallbackProvider` 装配（区别于流程用的 FlowTools），命名空间 `assistant_` 前缀防冲突。

## 5. SSE 事件协议

统一 `data: {json}\n\n`，`json.event` 取值：

| event | payload | 说明 |
| --- | --- | --- |
| `start` | `{conversationId}` | 会话确认（新建时前端据此记录） |
| `delta` | `{text}` | 增量文本，前端追加渲染 |
| `status` | `{text}` | 过程状态行（如「正在查询流程列表…」），前端显示后清除 |
| `tool_trace` | `[{name, arguments, result}]` | 工具调用轨迹，折叠展示 |
| `done` | `{content, model, promptTokens, completionTokens}` | 结束，含完整内容（防 delta 丢包可整体替换渲染） |
| `error` | `{message}` | 失败，前端展示重试按钮 |

心跳：每 15s 发 `: ping\n\n` 注释行防代理超时断连。

```markdown
# 角色
你是 guonl-spring-ai-flow 平台的内置 AI 助手「小流」，熟悉本平台全部功能。回答用中文、简洁、分点。

# 平台知识（摘要）
## 节点类型速查（13 种）
| 类型 | 用途 | 关键配置 |
| --- | --- | --- |
| TEXT 文本理解 | 纯文字输入 | prompt |
| IMAGE 图片识别 | 图片输入 | prompt, imageUrl |
| JSON / EXCEL | 结构化数据处理 | prompt（引用 {{input.rows}} 等） |
| COMBINED 组合 | 多源输入 | prompt + 图片 |

## 连线与路由
边 from→to（condition 仅 ROUTER 下游使用；空=默认边）。多上游即汇流点。
## 常见问题（FAQ 精简）
- 运行卡在 RUNNING：看节点超时（默认180s）与 provider 是否 llm 可用
- JSON 节点输出解析失败：检查 outputSpec 契约与温度（建议0.3）
- 知识库无命中：确认文档已向量化完成、topK
- MCP 接入：/guonl/ai/mcp (STATELESS/SYNC)

# 行为准则
1. 平台使用问题直接回答；涉及用户数据（流程/运行）先调用工具再回答，不编造。
```

## 9. 前端设计

### 9.1 assistant-chat.js（共享核心，无依赖）

- `AssistantChat` 类：`mount(container, {mode: 'drawer'|'page'})`——同一渲染逻辑两种容器。
- 职责：会话列表拉取/切换/删除、`fetch` + `ReadableStream` 解析 SSE、增量 markdown 渲染（标题/列表/表格/代码块/行内代码，自写 ~120 行轻量实现，不引第三方库）、工具轨迹折叠、错误重试、`localStorage` 记住最近会话。
- markdown 安全：渲染前 HTML 转义，仅白名单标签生成，防 XSS。

### 9.2 悬浮窗注入（common.js）

- `initAssistantLauncher()`：注入固定定位按钮（右下、footer 上方 48px），点击创建抽屉 DOM（400×560，随主题变量），首次打开动态 `import` assistant-chat.js 并挂载；`/assistant` 页面则跳过注入（避免双入口）。
- 状态角标：`/api/assistant/status` 的 provider=mock 时按钮加「M」小标。

### 9.3 独立页 assistant.html

- 布局：sidebar（复用 layout 片段）+ 三栏（会话列表 220px | 对话主区 flex | 快捷面板 260px，窄屏折叠）。
- 快捷卡片点击即发送预置 prompt；深浅色主题沿用 CSS 变量。
